ハンズオンに入る前に、GitやAnsibleの概要をイメージで頭に入れておきましょう。難しい理屈はさておき、感覚で理解するのがコツです。

## Gitとは

> [!NOTE]
> 一言でいうと、**『ファイルのセーブデータ管理システム』**です。

### 主な特徴
- **変更履歴の自動保存・追跡**: 「いつ、誰が、どこを変更したか」を細かく記録できます。
- **過去の状態への復元**: 間違えてファイルを書き換えてしまっても、過去の保存ポイント（コミット）にいつでも戻せます。
- **分岐（ブランチ）を使った同時作業**: メインのファイルを汚さずにコピー（枝分かれ）を作り、実験や新機能の追加を安全に進められます。のちに変更分を合体（マージ）できます。
- **オフラインでの作業**: 分散型のため、自分のパソコン（ローカル）に全履歴のコピーを持っており、インターネット接続がなくても作業や履歴確認が可能です。

### Git と GitHub の違い
よく混同されますが、役割が異なります。
- **Git**: 自分のパソコン上で、ファイルの変更履歴を管理する「ソフトウェア・仕組み」のこと。
- **GitHub**: Gitで管理している履歴やファイルをインターネット上で保存・共有し、複数人で協力して開発できるようにする「Webサービス」のこと。

## Gitの超ざっくり用語集

- **リポジトリ（Repository）**
  - 📦 **イメージ：「ファイルの倉庫」**
  - プロジェクトのファイルや変更履歴をすべて安全に保管しておく場所です。自分のPCにあるものを「ローカルリポジトリ」、GitHub上にあるものを「リモートリポジトリ」と呼びます。

- **コミット（Commit）**
  - 💾 **イメージ：「ゲームのセーブポイント」**
  - 「ここまで作業した！」という状態を歴史の1ページとして記録する操作です。こまめにコミットしておけば、いつでも過去の状態に戻せます。

- **ブランチ（Branch）**
  - 🌿 **イメージ：「パラレルワールド（枝分かれ）」**
  - メインの安全な世界（`main`）を汚さず、別世界で自由に実験や修正をするための枝葉です。ここでどれだけ失敗してもメインの世界には影響しません。

- **マージ（Merge）**
  - 🔀 **イメージ：「パラレルワールドの合流」**
  - 別世界（ブランチ）で作った成果物を、メインの世界（`main`）にドッキングして一つにする作業です。

- **コンフリクト（Conflict）**
  - ⚔️ **イメージ：「意見の食い違い（喧嘩）」**
  - 複数人で同じファイルの「同じ場所」を勝手にいじってしまい、Gitが「どっちの言う通りにすればいいのか分からない！」とパニックを起こした状態です。手動で直してあげる必要があります。

## Ansibleとは

> [!NOTE]
> 一言でいうと、**『設計書をもとにサーバ構築やファイル作成を完全自動化するツール』**です。

### 主な特徴
- **エージェントレスですぐに使える**: 管理対象のサーバーに専用プログラム（エージェント）をインストールする必要がありません。既存のSSH（Windowsの場合はWinRM）接続だけですぐに使えます。
- **YAML形式で分かりやすい**: 自動化の手順（Playbook）を人間が読み書きしやすいYAML（ヤムル）形式で記述するため、複雑なプログラミング言語の知識がなくても扱いやすいのが特徴です。
- **何度実行しても安全**: 何度同じ処理を実行しても、システムの状態が「正しい状態」になっていれば二重で変更が加わらない仕組みになっています。安全に何度でもテスト・実行が可能です。
- **豊富な標準モジュール**: OSのパッケージ管理やファイルの配置、サービスの起動などを行う多様なモジュールが標準で備わっているほか、CiscoやJuniperなどのネットワーク機器にも対応しています。
